# 语感标尺与范例

以下是本技能来源对话的风格样本。它们用于理解叙事机制，不是新闻证据。涉及平台规则和漏洞的现实信息，使用时另行核实。

## 用户提供的原始风格样本：农场与火鸡

> Anthropic 的农场里，住着一群中国火鸡，每月交钱供奉无所不能的 Claude。
>
> 唯一的问题是：神收香火，农场主不让进。
>
> 于是火鸡们买美国家宽、搭梯子、改指纹，甚至在美国托管 Mac mini——自己还没出过国，电脑已经移民了。给电脑编的美国人生，比自己的履历还完整。
>
> 一只火鸡科学家观察了九十九天，终于发表《Claude 防封终极指南》，宣布：“只要伪装得足够像美国火鸡，就能永享神恩。过去九十九天，就是铁证！”

这里可迁移的是：付款与准入的矛盾；自救成本逐步升级；电脑移民这一具体画面；把暂时幸存包装成确定知识。不要每次都续写“第一百天被封”，也不要把国籍当成应受嘲笑的理由。

## 对话中的虚构样本：审批

公司规定，程序员修改生产环境，必须提交工单，经过主管、安全、测试和业务四方审批，再等周末的发布窗口。

黑客不懂公司制度，直接进去了。

领导震怒：“为什么外部人员能绕过流程？”

安全部门连夜整改，给程序员又加了一道审批。

程序员问：“黑客呢？”

领导说：“他不是我们员工，管不了。”

月底，整改报告顺利通过验收：内部违规操作次数降为零。

服务器上那位外部人员，也一直没有提交过违规工单。

这里可迁移的是：审批这个同一道具，先表现管控，再暴露管控对象错位，最后变成自证成功的指标。结尾沿着组织自身的口径成立，无需追加“形式主义真可怕”。

## 对话中的虚构样本：免费门锁

互联网村里，住着一位叫 PHP 的老木匠。村民们平时都嫌他手艺落后，纷纷宣布要搬进现代化大楼。

宣布了十五年，收银台还放在他家。

一天，有人发现老木匠家的锁坏了，陌生人不用钥匙就能进来发号施令。全村立刻成立应急委员会，要求老木匠连夜修锁，并提交事故报告、整改方案和长期保障承诺。

老木匠说：“能不能先凑点钱，雇个人帮忙？”

村民们很失望：“开源精神怎么变味了？”

随后，各家花了几十万元，请咨询公司评估这把免费门锁带来的风险。

这里可迁移的是：嘴上嫌弃与实际依赖；对免费维护者的无限要求；用于维护和用于评估的预算错配。“十五年”“几十万元”都是虚构叙事细节，不可当作真实统计引用。

## 修改时的判断

- 如果只有“某技术很烂”，加入一个角色为了维持它而付出的具体代价。
- 如果只有一串吐槽，选一件道具，让人物的应对围绕它逐步升级。
- 如果反转凭空出现，回到开头埋下对应的规则、物品或承诺。
- 如果结尾后还想补一句道理，试着删掉；让读者自己完成最后一步。
