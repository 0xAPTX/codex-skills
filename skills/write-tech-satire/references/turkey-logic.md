# 火鸡逻辑的写作用法

这里提炼的是写作机制，不作哲学史考据。重点是有限观察如何被误当成普遍保证，以及故事如何揭露这种推论遗漏的条件。

## 两张表

火鸡的表记着“今天又得到了饲料”，于是推断“农场主爱我，而且会一直如此”。农场主的表可能记着体重、成本和出栏日期。双方观察同一过程，却有不同信息和目标。

写作前在心里回答：

- 主角看到了什么重复发生的好事？
- 它从中推出了哪个超出证据的保证？
- 这个保证让它多做了什么，付出了什么？
- 哪个关键条件一直不在它的视野里，或者不由它决定？
- 结尾出现什么细节，能让前面的证据变一个意思？

不要在成稿里列出这套分析。把它变成一次续费、一张称重表、一本指南或一句正经台词。

## 在平台题材中怎么用

“连续正常使用”只能说明观察期内正常，不能单独证明某种网络配置造成了安全，更不能保证外部规则和执行方式不变。角色可以把自己的说法写成“永久防封”，作者不应替它背书。

平台决定权不在用户手里，是可用的矛盾；平台特意养肥用户再封禁，是另一项需要证据的指控。若用农场主的阴谋作情节，保持寓言的虚构边界，不冒充真实公司的经营计划。

## 三个相邻但不同的笑点

- **归纳越界**：“我过去一直没出事，所以未来一定安全。”这是火鸡逻辑的核心。
- **幸存者偏差**：只统计还在群里的账号，出事的样本被移出了统计。
- **无法证伪的话术**：没封证明教程有效，封了证明环境真实。不管发生什么，卖家都说自己正确。

可将其中两个结合，但短篇通常选一个主机制即可。用户说要火鸡逻辑时，不能只写卖家狡辩而没有从经验到保证的越界。

## 反转不必靠屠刀

- 同一指标，两种解释：火鸡看到生存天数，农场主看到可售体重。
- 同一份指南，不同命运：经验的售卖还在继续，保证却已经失效。
- 同一笔投入，不同归属：主角为安全加码，钱却不能买来规则的决定权。
- 同一次异常，不同记账：模型遇到反例，专家选择删样本而不是改结论。

反转应从前文的利益或遗漏条件长出来。一个无关事故突然打断故事，只提供意外，不一定形成讽刺。

## 不要过度推论

观察期更长可以提供更多信息，但不自动消除未知条件。故事讽刺的是“保证”的越界，不是说经验和数据毫无价值。

也不要把风险画成必然逐日上升。若需要这个递进，可让主角因自信增加预付费、集中资产、扩大依赖；即使出事概率未知，暴露的损失也可以变大。出栏故事中体重增加才是明确的利益变化。
