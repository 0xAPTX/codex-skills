# 科技讽刺寓言

把真实矛盾写成简短的小故事：人物认真、语言平静、细节具体。让角色自己的判断和行动暴露荒诞，不由作者宣布谁愚蠢。

## 默认交付与反馈

- 默认只写一篇，约 80–180 个汉字、3–5 句；够用就停。保留一个具体细节、一处认知错位和一个收尾，不硬凑字数。
- 用户说“简单点”，压缩铺垫；说“没意思”“换一个”，更换矛盾或揭示方式，不能只删字、换角色或重写同一笑点。
- 除非用户要多个版本或分析，直接交正文，不附标题、创作说明、寓意总结和备选菜单。用户要求长篇时再展开。

## 火鸡逻辑：让证据在结尾变一个意思

用户要求结合“火鸡逻辑”时，先读 [references/turkey-logic.md](references/turkey-logic.md)。核心不是“第一百天突然倒霉”，而是：

1. **反复观察**：连续得到饲料、账号一直正常、老系统多年没出事。
2. **越界推论**：角色把这些记录当作永久安全的保证，因而加码付费、投资、依赖，或开始售卖经验。
3. **规则之外的变量**：角色看得到每天的饲料，看不到农场主的日历、目标和决定权。
4. **重新解释前文**：结尾让同一件好事显出另一层含义；喂养也可以是在准备出栏，稳定运行也可能只是漏洞尚未暴露。

不必每次写全四步，不固定第九十九天，也不强制出现屠刀。结尾可以停在称重表、规则变更、续费通知或一本仍在出售的指南上。让读者补出危险，比宣告“它死了”更有余味。

区分观察、因果和决定权：久未出事不证明某种伪装有效，也不证明平台永久许可。使用真实机构作背景时，不把未知规则写成蓄意诱骗的事实。

“过去安全不保证未来安全”不等于“时间越久必然越危险”。若写风险积累，交代增加的依赖、沉没投入、暴露面或出栏价值；否则不强加这个结论。

## 找到故事的受力点

先判断谁控制入口、谁付钱、谁劳动、谁承担风险，以及他们各自声称在追求什么。从一个最有力的矛盾入手，不必把所有问题写进一段。

可选机制，按题材取用，不逐项套模板：

- **付费不等于被接纳**：角色供奉服务，又自费伪装成有资格使用服务的人。
- **适应规则变成自我改造**：为了让电脑像美国用户，给电脑编的人生比本人履历还完整。
- **幸存被当成保证**：把过去没出事当作未来安全的证明，甚至写成指南出售；适用时使用上面的火鸡逻辑。
- **流程只约束服从者**：攻击者绕过审批，整改却给内部员工再加一道审批。
- **成本与价值错配**：不愿为基础维护付费，却肯为事故评估和漂亮报告花钱。
- **救火成功抹去救火价值**：人把问题解决了，组织据此证明不再需要这个人。

按题材选择机制，不为套“火鸡”把所有故事都写成农场。流程讽刺、沉没成本和无法证伪的话术可以独立成篇，不统称为火鸡逻辑。保持一个主要隐喻，别把每个技术名词都映射成动物或宗教用品。

## 写法

- 开头尽快交代人物的愿望和一个具体矛盾，少讲背景大道理。
- 短篇只保留必要的因果，每次应对在角色自身的利益或信念里说得通。需要递进时，让信心和投入一起增加，不堆砌事故。
- 放入少量只属于这个题材的细节，例如托管 Mac mini、浏览器指纹、工单、发布窗口、免费门锁。细节应参与因果，别堆术语。
- 人物说正经话，作者少用愤怒形容词。需要时借用“用户体验”“知识沉淀”“流程闭环”等话术，让行为自行拆穿它。
- 结尾用一个动作、一句通知、一项指标或一句平静回复，回扣前面的道具和规则。最后一句出来就收笔，不再解释寓意。
- 可以温和、辛辣或黑色幽默，按用户要求调整。锋芒主要指向权力、利益与制度的矛盾，不把受限制者的国籍或身份本身写成笑点。

## 涉及近期事件

用户提到“最近”“这次漏洞”或具体新闻时，先核实事件；技术事实优先查官方公告、项目维护者和原始披露。只提取故事需要的少量事实，不写成新闻综述。

- 保留事实边界：某些配置受影响不等于全网都能被接管，发现漏洞不等于已经攻破所有网站。
- 新闻背景与虚构情节分开。必要时在正文前用一句话说明经核实的背景并附来源，交代后文为借题发挥；引用不插进笑点里。
- 虚构人物的台词与行为不要冒充真实机构的原话或真实事故。不要把旧范例中的日期、编号和技术细节当作新热点事实复用。
- 用户提供完整素材且只要求改写时，可依素材创作；发现关键事实疑点则核实或改成明确的假设情境。无法核实时不编造新闻。

## 交付前修剪

检查角色行为是否有动机、升级是否有因果、结尾是否回扣。火鸡类故事还要检查：究竟把哪条经验误当成保证？结尾是否改变了这条经验的意义？如果只有“没被封，后来被封”，还缺认知上的反转。

删掉重复铺垫和“这说明了”“真正的问题是”等寓意解说。结尾不能只是把开头的坏消息再说一遍。

避免只复述“PHP 是世界上最好的语言”等熟梗；避免每篇都以封号、裁员、收费或 token 计数收尾。若换成任何公司或技术都成立，补回本题特有的矛盾与细节。

需要校准语感时，阅读 [references/examples.md](references/examples.md)。学它的因果与节奏，另写新情节，不机械复制标志性句子。原始长样本用于理解机制，不覆盖默认短篇要求。
